GCP Vertex AI Avatar Live Stream Flow Guide

Real-Time Full-Duplex Bidirectional Video & Audio Streaming Protocol Architecture

1 Overview of the GCP Flow

The AI Avatar live stream operates as a full-duplex bidirectional streaming WebSocket pipeline connected directly to Google Cloud Vertex AI's low-latency streaming cluster.

  1. Session Handshake: Client connects to Vertex AI over WebSocket and issues a setup configuration requiring the VIDEO response modality and target avatar persona.
  2. GCP Allocation: GCP Vertex AI acknowledges session creation and streams back a setupComplete confirmation containing a unique sessionId.
  3. User Speech Ingestion: Client captures user microphone audio at 16,000 Hz, encodes raw 16-bit linear PCM Little-Endian chunks, and transmits them upstream.
  4. Avatar Video Generation: GCP generates and streams back sequential fragmented MP4 chunks (video/mp4) containing lip-synced facial motion and synthesized voice.
  5. Client Playback: HTML5 MediaSource Extensions (MSE) appends the incoming MP4 chunks in sequence mode directly to the video element with sub-second latency.

4 Detailed Step-by-Step Flow & Payloads

Step 1: Upstream Authentication & WSS Handshake

The proxy establishes a WebSocket connection to Vertex AI passing the GCP Bearer token in the HTTP upgrade request:

GET //ws/google.cloud.aiplatform.v1beta1.LlmBidiService/BidiGenerateContent HTTP/1.1
Host: us-central1-aiplatform.googleapis.com
Upgrade: websocket
Connection: Upgrade
Authorization: Bearer ya29.a0AX07...
Content-Type: application/json

Step 2: Session Setup Frame (Client → GCP)

The very first payload sent specifies model resource name, "VIDEO" response modality, voice, and avatar:

{
  "setup": {
    "model": "projects/my-gcp-project/locations/global/publishers/google/models/gemini-3.8-live",
    "generationConfig": {
      "responseModalities": [
        "VIDEO"
      ],
      "speechConfig": {
        "voiceConfig": {
          "prebuiltVoiceConfig": {
            "voiceName": "fenrir"
          }
        }
      }
    },
    "avatarConfig": {
      "avatarName": "Jay"
    },
    "systemInstruction": "You are a warm, world-class 1-on-1 AI Tutor...",
    "inputAudioTranscription": {},
    "outputAudioTranscription": {}
  }
}

Step 3: Setup Confirmation (GCP → Client)

GCP validates the request and acknowledges with the session identifier:

{
  "setupComplete": {
    "sessionId": "8a7061ff-0c2e-49c5-ae70-0c8006efcbe4"
  }
}

Step 4: Real-Time Audio Ingestion (Client → GCP)

Microphone audio is captured at 16,000 Hz, converted to 16-bit linear PCM Little-Endian, and streamed continuously:

{
  "realtimeInput": {
    "mediaChunks": [
      {
        "mimeType": "audio/pcm;rate=16000",
        "data": "AP///wEAAAD9//7/..."
      }
    ]
  }
}

Step 5: Fragmented MP4 Video Delivery (GCP → Client)

GCP streams sequential fragmented MP4 boxes containing video and synchronized audio:

{
  "serverContent": {
    "modelTurn": {
      "parts": [
        {
          "inlineData": {
            "mimeType": "video/mp4",
            "data": "AAAAHGZ0eXBkYXNoAAAAAGlzbzZhdmMxbXA0MQAABKltb29mAAAA..."
          }
        }
      ]
    },
    "outputTranscription": {
      "text": "Hello! I am ready to guide you."
    }
  }
}
  • Container: Fragmented MP4 (ftyp + moof + mdat per segment).
  • Video Codec: H.264 / AVC (avc1.42E01E).
  • Audio Codec: AAC (mp4a.40.2).

Step 6: Client Playback via MediaSource Extensions (MSE)

HTML5 MediaSource decodes incoming buffers directly into the video element:

// 1. Initialize MediaSource
const mediaSource = new MediaSource();
videoElement.src = URL.createObjectURL(mediaSource);

mediaSource.addEventListener('sourceopen', () => {
  const sourceBuffer = mediaSource.addSourceBuffer('video/mp4; codecs="avc1.42E01E, mp4a.40.2"');
  sourceBuffer.mode = 'sequence'; // Sequence mode for continuous chunking
});

// 2. Append incoming base64 video chunks
function onVideoChunkReceived(base64Data) {
  const binaryData = Uint8Array.from(atob(base64Data), c => c.charCodeAt(0));
  sourceBuffer.appendBuffer(binaryData.buffer);
}

// 3. Prune old buffer (keep last 5 seconds to avoid high memory)
if (videoElement.currentTime > 6 && !sourceBuffer.updating) {
  sourceBuffer.remove(0, videoElement.currentTime - 5);
}

Step 7: Barge-in / Interruption Handling

If the user speaks while the avatar is talking, GCP halts video generation and returns an interruption signal:

{
  "serverContent": {
    "interrupted": true
  }
}

Client immediately flushes the pending video buffer queue and switches the avatar back to the active listening state.

Step 8: Turn Completion

When the avatar finishes its response, GCP signals turn completion:

{
  "serverContent": {
    "turnComplete": true
  }
}
